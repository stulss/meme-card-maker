# 과제 요구사항 ↔ 설계 매핑표

**관련 문서:** [[meme-card-maker/README|README]] · [[meme-card-maker/검증안내서|검증안내서]] · [[meme-card-maker/AI_3줄|AI 3줄]] · [[meme-card-maker/docs/01_기획|기획]]

> 과제: **카드·밈 제작 웹 도구** (과제 카드 5개)
> 이 문서는 **각 카드의 통과 기준이 어느 파일/함수에서 충족되는지**를 1:1로 대응시킨다.

---

## 카드 1 — 편집과 미리보기

**통과 기준**: 이미지와 문구를 고르는 조작이 보이고, 한 번 바꾼 값이 미리보기에 즉시 반영된다.

| 요구 | 대응 |
|---|---|
| PNG·JPEG 이미지 불러오기 | `#image-input` (`accept="image/png,image/jpeg"`) → `EditorController._onImageSelected` |
| 문구 위치·크기·색 변경 | `#pos-x/y`, `#box-w/h`, `#max-font-size`, `#text-color` 슬라이더/피커 → `EditorController._bindEvents` |
| 즉시 미리보기 반영 | 모든 입력 이벤트가 `scheduleRender()` 호출 → `CardRenderer.renderCard`가 `#preview-canvas`에 즉시 그림 |
| 미지원 파일 방어 | `_onImageSelected`에서 MIME 검사 실패 시 alert만 띄우고 기존 편집 상태·템플릿은 그대로 유지 |

**학생 자체 점검**: PNG/JPEG 각각 업로드 후 문구 위치·크기·색 변경 시 실시간 반영 확인 완료
(브라우저 세션에서 직접 조작, 스크린샷: `img/parity/`, `img/samples/` 참고 — 편집 결과가
그대로 export 파일로 이어짐을 증명).

---

## 카드 2 — 화면과 파일의 일치

**통과 기준**: 1:1·4:5·9:16에서 미리보기와 내려받은 이미지의 배치가 같다.

| 요구 | 대응 |
|---|---|
| 세 비율이 화면에서 구분됨 | `.ratio-btn[data-ratio]` 3개, 선택 시 `.active` 클래스 + `aria-pressed` |
| 화면=파일 구조적 보장 | `CardRenderer.renderCard()` 단 하나의 함수가 미리보기와 다운로드 양쪽에서 호출됨 (`js/render/CardRenderer.js`) — 별도 export 캔버스 없음 |
| 해상도 프리셋 | `CardRenderer.RATIO_PRESETS = {1:1→1080×1080, 4:5→1080×1350, 9:16→1080×1920}` |
| devicePixelRatio 미사용 | 렌더 좌표 계산 어디에도 `devicePixelRatio`를 곱하지 않음 — 화면 표시 크기(CSS)와 실제 export 해상도(canvas 속성)가 분리되어 있어 항상 일치 |

**검증 방법**: `img/parity/ratio-1x1.png`, `ratio-4x5.png`, `ratio-9x16.png` — 실제로
canvas에서 `toDataURL()`로 추출한 파일이며, 브라우저 화면의 canvas와 동일한 bitmap.

## 카드 3 — 극단 입력 검사

**통과 기준**: 긴 한글·줄바꿈·이모지가 들어간 예제에서도 문구가 잘리거나 겹치지 않는다.

| 요구 | 대응 |
|---|---|
| 12개 극단 입력 | `js/models/FixtureData.js`의 `TEXT_CASES` 배열 (긴한글/긴영문/한영혼합/수동줄바꿈/이모지/빈문자열/한글자/거대토큰/기호집약/숫자단위/오버플로우강제/공백탭혼합) |
| 자동 축소 | `TextLayout.fitAndDraw()`의 이진 탐색 (10px~maxFontSizePx) |
| 잘림·겹침 방지 | `ctx.clip()` 안전망 — 상자를 벗어나는 렌더를 물리적으로 차단 |
| grapheme-safe 줄바꿈 | `Intl.Segmenter`로 이모지 합성 시퀀스 보존 |
| 결과 기록 | `docs/03_엣지케이스_테스트_결과.md` — 12개 × 5개 이미지 = 36+개 조합 실제 렌더 테스트 결과 |

**대표 결함 수정 전·후**: `img/edge-cases/clip-overflow-before.png`(결함: 클립 비활성 시
텍스트가 상자 밖으로 크게 넘침) vs `clip-overflow-after.png`(수정 후: 상자 안에 정확히
클립됨). 빨간 테두리가 의도한 텍스트 상자.

## 카드 4 — 실제 템플릿 관리

**통과 기준**: 템플릿 만들기·불러오기·수정·삭제 조작이 화면에 보인다.

| 요구 | 대응 |
|---|---|
| 하드코딩 아님 | `TemplateStore`(`js/models/TemplateStore.js`)가 실제 `localStorage` CRUD 수행. 화면에는 3개가 아니라 사용자가 만든 개수만큼 표시됨 |
| 생성 | `#template-save-new-btn` → `TemplateController._saveNew` → `TemplateStore.create` |
| 불러오기 | 목록의 "불러오기" 버튼 → `TemplateController._load` → `EditorController.loadCardState` |
| 수정 | `#template-update-current-btn` → `TemplateController._updateCurrent` → `TemplateStore.update` |
| 삭제 | 목록의 "삭제" 버튼(확인 다이얼로그 포함) → `TemplateController._delete` → `TemplateStore.remove` |
| 새로고침 후 유지 | `TemplateStore.load()`가 매번 `localStorage`에서 직접 읽음 — 메모리 캐시 없음 |

**검증**: 실제 브라우저 UI에서 "인스타 공지 카드"(1:1) · "카드뉴스 표지"(4:5) ·
"스토리 광고"(9:16) 3개 템플릿을 버튼 클릭으로 생성 → `TemplateStore.getAll()`로
3개 확인 → 새로고침 후에도 유지 확인.

---

## 카드 5 — 옆겨 쓰기 (가져오기/내보내기)

**통과 기준**: 가져오기·내보내기·내려받기 조작과 공개 정보 안내가 화면에 보인다.

| 요구 | 대응 |
|---|---|
| 내보내기 | `#export-json-btn` → `ImportExportController._exportJson` → `{version,exportedAt,templates}` JSON 다운로드 |
| 가져오기 | `#import-json-input` → `ImportExportController._importJson` |
| JSON 문법 오류 거부 | `JSON.parse` try/catch 실패 시 즉시 거부, 저장소 불변 — fixture: `tools/fixtures/import-invalid/broken-syntax.json` |
| 필수 항목 누락 거부 | `validateImportPayload()`가 유효 항목 0개면 거부 — fixture: `tools/fixtures/import-invalid/missing-fields.json` |
| 기존 템플릿 보존 | `TemplateStore.appendImported()`는 항상 append이며 절대 replace하지 않음 |
| 공개 정보 안내 문구 | `index.html`의 `.privacy-note` — "브라우저(localStorage)에만 저장, 서버 전송 없음" 명시 |
| 완성 이미지 3개 | `img/samples/sample-1-square.png`(1:1) · `sample-2-4x5.png`(4:5) · `sample-3-9x16.png`(9:16) |

**검증**: 두 invalid fixture 모두 콘솔/로직 레벨에서 거부 확인, `appendImported`가
기존 목록을 교체하지 않고 뒤에 추가하는 것을 코드 레벨에서 확인(교체 코드 경로 자체가 없음).
