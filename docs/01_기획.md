# 기획 — 이미지+문구 카드 메이커

**관련 문서:** [[meme-card-maker/README|README]] · [[meme-card-maker/작업내역_체크리스트|작업내역 체크리스트]]

## 왜 이 도구인가

밈·카드뉴스·SNS 게시용 이미지를 빠르게 만들고 싶은 사람을 위한, 설치·가입 없는
브라우저 편집기. 핵심은 "미리보기에서 본 것과 다운로드한 파일이 항상 똑같다"는
신뢰와, "아무리 이상한 문구를 넣어도 깨지지 않는다"는 안정성이다.

## 기술 스택 선택

| 결정 | 이유 |
|---|---|
| 순수 HTML/CSS/JS (빌드 도구 없음) | 정적 파일이라 어떤 정적 호스팅에도 바로 배포 가능. 같은 작업공간의 다른 프로젝트(`odd-one-out`, `webtest`)와 관례 통일 |
| Canvas 2D API | 이미지 합성·텍스트 렌더링·PNG/JPEG export를 브라우저 표준 API만으로 처리 가능 |
| localStorage | 서버 없이 템플릿을 저장. 사용자 이미지가 외부로 전송되지 않아 개인정보 보호에 유리 |
| MVC 유사 구조 (models/render/views/controllers) | 같은 작업공간(`webtest`)의 기존 관례를 따름. 프레임워크 없이도 관심사 분리 |

> 참고: 함께 검토한 `card_meme_web_tool_development_request.md`(React+TypeScript+Konva.js
> 기반의 훨씬 큰 프로덕션 PRD)의 스택은 채택하지 않았다. 과제 카드 5개 통과가
> 목표이므로 레이어 시스템·스티커·실행취소 등은 범위 밖으로 두고, 테스트 문구·오류
> 메시지 톤·EXIF 제거 원칙 등 콘텐츠 수준의 아이디어만 선별적으로 반영했다.
> 근거: `.claude/plans/key-velvet-kahan.md`의 "참고 문서 검토 및 범위 조정" 섹션.

## 렌더링 아키텍처 (화면=파일 일치의 핵심)

미리보기와 다운로드가 **같은 `<canvas>` 엘리먼트**를 사용한다. 별도의 export 전용
canvas가 없다. `canvas.width`/`height` 속성이 곧 실제 export 해상도이며(1080×1080,
1080×1350, 1080×1920), CSS는 화면에 보여주는 크기만 조정할 뿐 내부 버퍼는 건드리지
않는다. `devicePixelRatio`는 draw 좌표 계산에 의도적으로 사용하지 않는다 — 그러면
화면과 파일의 좌표가 어긋날 수 있기 때문이다. 다운로드 버튼을 누르면 마지막으로
본 상태를 다시 한 번 같은 함수(`CardRenderer.renderCard`)로 렌더링한 뒤 그 canvas의
bitmap을 그대로 `toBlob()`으로 추출한다.

## 텍스트 레이아웃 알고리즘

`js/render/TextLayout.js`가 담당한다.

1. **수동 줄바꿈 우선**: `\n`은 항상 줄바꿈으로 존중한다.
2. **토큰화**: 공백 기준으로 1차 분할해 영어 단어 줄바꿈과 한영 혼합을 지원한다.
3. **grapheme 분해**: 상자 폭을 넘는 토큰(긴 한글 연속, 거대한 미분할 토큰)은
   `Intl.Segmenter`로 grapheme(글자 모음) 단위로 재분해한다. 이렇게 하면 이모지
   합성 시퀀스(ZWJ, 국기, 피부톤 modifier)가 코드 포인트 단위로 잘리지 않고
   하나의 단위로 유지된다. `Intl.Segmenter`가 없는 구형 브라우저에서는
   코드 포인트(`Array.from`) 단위로 대체된다.
4. **이진 탐색 자동 축소**: 선형으로 폰트 크기를 하나씩 줄이지 않고, `[10px, 최대값]`
   구간에서 상자에 맞는 가장 큰 크기를 이진 탐색으로 찾는다. 레이아웃 계산 횟수가
   훨씬 적다.
5. **클립 안전망**: 최소 크기(10px)에서도 넘치면 `ctx.clip()`으로 상자 밖 렌더링을
   차단한다. 텍스트가 이미지 밖으로 튀어나오거나 다른 UI를 가리지 않는다.
6. **측정=paint 일치**: 줄 나누기에 쓴 것과 동일한 폰트 크기·baseline 계산으로
   그린다. 측정과 그리기가 다른 기준을 쓰면 1~2px 단위로 클립이 어긋날 수 있다.

## LocalStorage 템플릿 스키마

```
meme-card-maker:templates:v1 → { version: 1, templates: TemplateRecord[] }

TemplateRecord = {
  id, name, createdAt, updatedAt,
  ratio: "1:1" | "4:5" | "9:16",
  imageFitMode: "cover" | "contain",
  imageDataUrl: string | null,
  backgroundColor: "#rrggbb",
  text: {
    content, color, xRatio, yRatio, wRatio, hRatio,
    maxFontSizeRatio, align, fontFamily
  }
}
```

업로드 이미지는 저장 전에 최대 1280px로 downscale하고, 알파 채널이 있으면 PNG로
없으면 JPEG(quality 0.85)로 인코딩한다. localStorage quota(보통 5~10MB)를 템플릿
2~3개만으로 소진하지 않기 위한 조치다.

## Import/Export 설계

내보내기는 `{version, exportedAt, templates}`를 JSON으로 직렬화해 다운로드한다.
가져오기는 다음 순서로 처리한다.

1. `JSON.parse` 실패 → 즉시 거부, 저장소 그대로 유지
2. 각 레코드를 스키마 검사해 유효/무효로 분리
3. 유효한 레코드가 0개면 거부
4. 유효한 레코드만 **새 ID를 부여해 append** — 기존 목록을 절대 교체하지 않는다

4번이 핵심이다. import 경로 어디에도 "전체 교체" 코드가 없으므로, 고장난 파일이
기존 템플릿을 파괴하는 것이 구조적으로 불가능하다.

## 이미지·문구 자동 생성 (v1.1)

매번 이미지를 준비하거나 문구를 직접 떠올려야 하는 번거로움을 줄이기 위해 추가했다.

- **이미지 자동 생성** (`js/render/AutoImageGenerator.js`): 8종의 색상 팔레트 ×
  3종의 도형 스타일(원/줄무늬/삼각형)을 무작위 조합해 현재 화면비 해상도에 맞는
  배경 이미지를 그 자리에서 canvas로 그려 dataURL로 만든다. 업로드 이미지와
  동일하게 `cardState.imageDataUrl`에 들어가므로 기존 렌더링 파이프라인
  (`ImageFit` → `CardRenderer`)을 그대로 재사용한다.
- **문구 자동 생성** (`js/models/PhraseTemplates.js`): 응원·감성·유머·공지·축하
  5개 카테고리로 큐레이션한 문구 중에서 무작위로 하나를 골라 채운다. 외부 AI
  텍스트 생성 API를 쓰지 않은 이유: 서버·API 키·비용이 필요해 "서버 없는 순수
  클라이언트 앱"이라는 이 프로젝트의 기본 원칙과 맞지 않는다.
- 두 기능 모두 **완전히 선택적**이다 — 버튼을 누르지 않으면 기존처럼 직접
  업로드/입력한 값이 그대로 쓰이고, 자동 생성 후에도 언제든 값을 덮어써 수정할
  수 있다.

## 야구 모드 — 날짜별 KBO 경기 결과 카드 (v1.2)

날짜를 고르면 그날의 KBO 경기 목록이 뜨고, 경기를 선택하면 배경 이미지와 문구가
자동으로 채워진다.

### 데이터 확보 방식

KBO 공식 사이트는 공개 API를 제공하지 않지만, 사이트 내부에서 쓰는 웹서비스
엔드포인트(`/ws/Schedule.asmx/GetScheduleList`)가 JSON을 반환한다는 것을 확인했다.
HTML을 통째로 긁는 것보다 이쪽이 훨씬 안정적이라 이 엔드포인트를 사용한다.

- 요청 형식: `POST`, `application/x-www-form-urlencoded`,
  본문 `leId=1&srIdList=0,9,6&seasonId=YYYY&gameMonth=MM&teamId=`
- 응답: 화면 표를 그대로 담은 `rows` 구조. 각 셀의 HTML을 파싱해
  `{date, dateLabel, time, awayTeam, homeTeam, awayScore, homeScore, played, stadium, note}`
  형태로 정규화한다.
- 무승부(점수 같음), 취소 경기(점수 없음 + `note`에 '폭염취소' 등)를 구분해 처리한다.

### 왜 서버리스 함수가 필요한가

브라우저에서 KBO 사이트로 직접 `fetch`하면 CORS 정책에 막힌다(실제로 확인함).
그래서 `api/kbo-schedule.js` 서버리스 함수가 대신 호출하고 정제된 JSON만 돌려준다.

### 캐싱 전략 (cron 없이)

"하루 한 번 크롤링하는 cron이 필요한가?"를 검토했으나, **CDN 캐시만으로 충분**하다고
판단했다.

- 과거 날짜: 결과가 확정이므로 `s-maxage=86400`(1일)
- 오늘/미래 날짜: 경기가 진행 중일 수 있으므로 `s-maxage=600`(10분)

cron 방식은 아무도 조회하지 않는 날짜까지 매일 긁어 KBO 서버에 불필요한 부하를 준다.
반면 이 방식은 **실제로 조회된 달만, 캐시가 만료됐을 때만** 가져오므로 요청 수가
훨씬 적고 별도 DB나 스케줄러도 필요 없다.

### 카드 생성 규칙

**핵심 설계**: 단순히 배경색만 칠하고 그 위에 텍스트 레이어를 얹는 방식이 아니라,
**경기 결과 자체를 스코어보드 그래픽으로 이미지에 직접 그려 넣는다**
(`BaseballCardGenerator.generateScoreboard`). 이미지 하나만으로 카드가 완성되므로
텍스트 레이어는 기본적으로 비워둔다.

스코어보드 구성:
- **좌우 팀 색상 분할**: 왼쪽 원정팀, 오른쪽 홈팀의 상징색. **패배팀 쪽은 어둡게**
  처리해 결과가 한눈에 보인다. 무승부는 양쪽 다 밝게, 미개최 경기는 전체를 어둡게.
- **상단**: 날짜 · 구장
- **중앙**: 팀 약칭, 원정/홈 표시, 큰 점수(패배팀 점수는 흐리게), 승리팀 쪽 `WIN` 배지.
  미개최 경기는 점수 대신 `VS`.
- **하단**: 결과 문구(`○○ 승리` / `무승부` / `폭염취소` 등)와 경기 시간
- **구단 로고·엠블럼 이미지는 저작권 때문에 사용하지 않고 색상만 활용한다.**

문구는 **덧붙이는 코멘트** 역할로 축소됐다(`generatePhrase`). 기본값은 '없음'이며,
원하면 `headline`(승리팀 강조, 점수 차에 따라 '완승!'/'한 점 차 승부!' 자동 선택),
`summary`, `score` 중에서 고르거나 직접 입력할 수 있다. 코멘트는 스코어보드 본문과
겹치지 않도록 하단 여백에 배치된다.

자동 생성 후에도 기존 편집 패널로 문구·색·위치를 자유롭게 수정할 수 있다.

## 생성형 AI 이미지 (선택 기능, v1.3)

OpenAI **GPT Image 2**를 **선택 기능**으로 연동했다.

### 모델 선택 근거

Google Gemini("Nano Banana")와 비교 검토한 뒤 GPT Image 2를 택했다.

| 항목 | GPT Image 2 (채택) | Gemini 이미지 |
|---|---|---|
| 1024×1024 저품질 | 약 $0.006 (≈9원) | 약 $0.034 (≈50원) |
| 생태계 | Vercel에서 사용량이 가장 많음 | — |

**품질은 `low`를 기본값으로 쓴다.** 이 이미지는 배경으로만 쓰이고 그 위에 팀 색상
오버레이(62%)와 그라디언트 음영이 덮인 뒤 텍스트가 올라간다. 고품질을 써도 최종
결과 차이가 거의 없는 반면 비용은 30배 이상 차이나기 때문이다
(1024×1024 기준 `low` ≈ $0.006, `high` ≈ $0.211). 필요하면
`OPENAI_IMAGE_QUALITY` 환경변수로 올릴 수 있다.

화면비는 `1:1 → 1024x1024`, `4:5`·`9:16 → 1024x1536`으로 매핑한다. 정확히
대응하는 값이 없지만 최종 렌더링에서 `cover`로 잘라 채우므로 세로형이면 충분하다.

### 역할 분담: AI는 분위기, 코드는 사실

야구 카드에서 AI에게 **경기 결과를 그리게 하지 않는다.** AI는 "야구장 분위기 배경"만
만들고, 팀명·점수·승패는 기존 스코어보드 렌더링이 그 위에 정확하게 그린다.
AI 프롬프트에 팀명이나 점수를 넣지 않는 이유도 같다 — AI가 글자를 그려 넣으면 실제
결과와 어긋날 수 있기 때문이다.

일반 카드는 사용자가 직접 프롬프트를 입력해 배경을 만든다.

### 프롬프트 자동 생성 (야구 모드)

"카드 만들기"를 누르면 `BaseballPromptBuilder`가 경기 데이터로 포스터 프롬프트를
자동 작성한다. 사용자가 프롬프트를 몰라도 결과가 나오고, 원하면 화면에서 직접
고쳐 재생성할 수도 있다.

자동으로 반영되는 것:

| 데이터 | 프롬프트 반영 |
|---|---|
| 점수 차 | 7점 이상 "압도적 승리" / 1점 차 "한 점 차 스릴러" / 무승부 / 취소 — 분위기 자동 선택 |
| 승패 | 승리팀은 왼쪽에 승리 포즈·밝은 조명, 패배팀은 오른쪽에 어둡게 |
| 팀 | 각 구단 마스코트 실명 + 생김새 설명 + 팀 컬러 |
| 구장 | 한글명을 영문명으로 변환 (고척 → Gocheok Sky Dome, indoor domed stadium) |
| 시간 | 18시 이후면 야간 조명, 아니면 주간 |
| 스코어 | "가장 크고 명확하게 읽히도록" 지시 + **다른 숫자가 나오지 않도록 네거티브 지정** |

> AI가 스코어보드 숫자를 틀리게 그릴 위험이 있어 네거티브 프롬프트로 방지하지만
> 완벽하지는 않다. 정확성이 중요하면 AI 옵션을 끄고 코드가 그리는 스코어보드를
> 쓰면 된다 (숫자가 100% 정확하다).

> 마스코트 실명 사용에 대해: 이 프로젝트는 **과제 제출용 임시 사이트이며 제출 후
> 내릴 예정**이라는 전제로 실명을 쓴다. 상시 서비스로 전환한다면 구단 캐릭터·로고
> 사용에 대해 별도 확인이 필요하다.

| API 키 노출 | 서버 환경변수(`OPENAI_API_KEY`)로만 취급. 브라우저에 절대 내려보내지 않음 |
| 키 미설정 | 서버가 `503 NO_API_KEY` 반환 → 프런트엔드가 기존 절차적 생성으로 자동 대체하고 이유를 표시 |
| 요금 폭증 | 프롬프트 길이 제한(400자) + 간이 일일 한도(`AI_IMAGE_DAILY_LIMIT`, 기본 100) + 저품질 기본값 |
| 콘텐츠 정책 위반 | 400으로 구분해 "다른 표현으로 시도해 주세요"라고 안내 |
| AI 실패 | 항상 기본 배경으로 대체. **AI 없이도 앱의 모든 기능이 완전히 동작한다** |

> 서버리스는 인스턴스가 여러 개일 수 있어 간이 한도가 완벽하지는 않다. 실제 운영
> 시에는 OpenAI 대시보드의 **사용량 한도(usage limits)** 를 함께 설정해야 한다.

### 설정 방법

1. [platform.openai.com](https://platform.openai.com/api-keys)에서 API 키 발급
2. Vercel 프로젝트 → Settings → Environment Variables에 `OPENAI_API_KEY` 등록
3. 재배포하면 AI 기능이 동작한다 (키가 없으면 버튼은 보이되 안내 메시지가 뜬다)

선택 환경변수: `OPENAI_IMAGE_MODEL`(기본 `gpt-image-2`),
`OPENAI_IMAGE_QUALITY`(기본 `low`), `AI_IMAGE_DAILY_LIMIT`(기본 100).

### 한계 및 주의

KBO가 공식 허가한 API가 아니라 사이트 내부 엔드포인트이므로, KBO가 구조를 바꾸면
동작하지 않을 수 있다. 개인 학습·비상업적 용도 범위에서 사용하는 것을 전제로 한다.

## 개인정보·저작권

- 업로드 이미지는 서버로 전송되지 않고 브라우저(localStorage)에만 저장된다 — 화면에
  안내 문구로 명시.
- 검사용 샘플 이미지 5종(`assets/sample-images/`)은 전부 Python(Pillow)의 도형·
  그라디언트로 직접 그려 생성했다. 사진이 아니므로 EXIF/위치 정보가 애초에 없고,
  저작권 문제도 없다. (재현 가능한 브라우저 버전: `tools/generate-fixtures.html`)
- 사용자가 업로드하는 실제 이미지의 EXIF 제거는 이 도구의 책임 범위가 아니지만,
  화면 안내 문구에서 "개인정보·위치 정보가 없는지 직접 확인"하도록 안내한다.
