# 기획 — 이미지+문구 카드 메이커

**관련 문서:** [[meme-card-maker/README|README]] · [[meme-card-maker/작업내역_체크리스트|작업내역 체크리스트]]

## 왜 이 도구인가

밈·카드뉴스·SNS 게시용 이미지를 빠르게 만들고 싶은 사람을 위한, 설치·가입 없는
브라우저 편집기. 핵심은 "미리보기에서 본 것과 다운로드한 파일이 항상 똑같다"는
신뢰와, "아무리 이상한 문구를 넣어도 깨지지 않는다"는 안정성이다.

## 기술 스택 선택

| 결정 | 이유 |
|---|---|
| 순수 HTML/CSS/JS (빌드 도구 없음) | 정적 파일이라 어떤 정적 호스팅에도 바로 배포 가능. 같은 작업공간의 다른 프로젝트(`odd-one-out`, `webtest`)와 관례 통일 |
| Canvas 2D API | 이미지 합성·텍스트 렌더링·PNG/JPEG export를 브라우저 표준 API만으로 처리 가능 |
| localStorage | 서버 없이 템플릿을 저장. 사용자 이미지가 외부로 전송되지 않아 개인정보 보호에 유리 |
| MVC 유사 구조 (models/render/views/controllers) | 같은 작업공간(`webtest`)의 기존 관례를 따름. 프레임워크 없이도 관심사 분리 |

> 참고: 함께 검토한 `card_meme_web_tool_development_request.md`(React+TypeScript+Konva.js
> 기반의 훨씬 큰 프로덕션 PRD)의 스택은 채택하지 않았다. 과제 카드 5개 통과가
> 목표이므로 레이어 시스템·스티커·실행취소 등은 범위 밖으로 두고, 테스트 문구·오류
> 메시지 톤·EXIF 제거 원칙 등 콘텐츠 수준의 아이디어만 선별적으로 반영했다.
> 근거: `.claude/plans/key-velvet-kahan.md`의 "참고 문서 검토 및 범위 조정" 섹션.

## 렌더링 아키텍처 (화면=파일 일치의 핵심)

미리보기와 다운로드가 **같은 `<canvas>` 엘리먼트**를 사용한다. 별도의 export 전용
canvas가 없다. `canvas.width`/`height` 속성이 곧 실제 export 해상도이며(1080×1080,
1080×1350, 1080×1920), CSS는 화면에 보여주는 크기만 조정할 뿐 내부 버퍼는 건드리지
않는다. `devicePixelRatio`는 draw 좌표 계산에 의도적으로 사용하지 않는다 — 그러면
화면과 파일의 좌표가 어긋날 수 있기 때문이다. 다운로드 버튼을 누르면 마지막으로
본 상태를 다시 한 번 같은 함수(`CardRenderer.renderCard`)로 렌더링한 뒤 그 canvas의
bitmap을 그대로 `toBlob()`으로 추출한다.

## 텍스트 레이아웃 알고리즘

`js/render/TextLayout.js`가 담당한다.

1. **수동 줄바꿈 우선**: `\n`은 항상 줄바꿈으로 존중한다.
2. **토큰화**: 공백 기준으로 1차 분할해 영어 단어 줄바꿈과 한영 혼합을 지원한다.
3. **grapheme 분해**: 상자 폭을 넘는 토큰(긴 한글 연속, 거대한 미분할 토큰)은
   `Intl.Segmenter`로 grapheme(글자 모음) 단위로 재분해한다. 이렇게 하면 이모지
   합성 시퀀스(ZWJ, 국기, 피부톤 modifier)가 코드 포인트 단위로 잘리지 않고
   하나의 단위로 유지된다. `Intl.Segmenter`가 없는 구형 브라우저에서는
   코드 포인트(`Array.from`) 단위로 대체된다.
4. **이진 탐색 자동 축소**: 선형으로 폰트 크기를 하나씩 줄이지 않고, `[10px, 최대값]`
   구간에서 상자에 맞는 가장 큰 크기를 이진 탐색으로 찾는다. 레이아웃 계산 횟수가
   훨씬 적다.
5. **클립 안전망**: 최소 크기(10px)에서도 넘치면 `ctx.clip()`으로 상자 밖 렌더링을
   차단한다. 텍스트가 이미지 밖으로 튀어나오거나 다른 UI를 가리지 않는다.
6. **측정=paint 일치**: 줄 나누기에 쓴 것과 동일한 폰트 크기·baseline 계산으로
   그린다. 측정과 그리기가 다른 기준을 쓰면 1~2px 단위로 클립이 어긋날 수 있다.

## LocalStorage 템플릿 스키마

```
meme-card-maker:templates:v1 → { version: 1, templates: TemplateRecord[] }

TemplateRecord = {
  id, name, createdAt, updatedAt,
  ratio: "1:1" | "4:5" | "9:16",
  imageFitMode: "cover" | "contain",
  imageDataUrl: string | null,
  backgroundColor: "#rrggbb",
  text: {
    content, color, xRatio, yRatio, wRatio, hRatio,
    maxFontSizeRatio, align, fontFamily
  }
}
```

업로드 이미지는 저장 전에 최대 1280px로 downscale하고, 알파 채널이 있으면 PNG로
없으면 JPEG(quality 0.85)로 인코딩한다. localStorage quota(보통 5~10MB)를 템플릿
2~3개만으로 소진하지 않기 위한 조치다.

## Import/Export 설계

내보내기는 `{version, exportedAt, templates}`를 JSON으로 직렬화해 다운로드한다.
가져오기는 다음 순서로 처리한다.

1. `JSON.parse` 실패 → 즉시 거부, 저장소 그대로 유지
2. 각 레코드를 스키마 검사해 유효/무효로 분리
3. 유효한 레코드가 0개면 거부
4. 유효한 레코드만 **새 ID를 부여해 append** — 기존 목록을 절대 교체하지 않는다

4번이 핵심이다. import 경로 어디에도 "전체 교체" 코드가 없으므로, 고장난 파일이
기존 템플릿을 파괴하는 것이 구조적으로 불가능하다.

## 개인정보·저작권

- 업로드 이미지는 서버로 전송되지 않고 브라우저(localStorage)에만 저장된다 — 화면에
  안내 문구로 명시.
- 검사용 샘플 이미지 5종(`assets/sample-images/`)은 전부 Python(Pillow)의 도형·
  그라디언트로 직접 그려 생성했다. 사진이 아니므로 EXIF/위치 정보가 애초에 없고,
  저작권 문제도 없다. (재현 가능한 브라우저 버전: `tools/generate-fixtures.html`)
- 사용자가 업로드하는 실제 이미지의 EXIF 제거는 이 도구의 책임 범위가 아니지만,
  화면 안내 문구에서 "개인정보·위치 정보가 없는지 직접 확인"하도록 안내한다.
