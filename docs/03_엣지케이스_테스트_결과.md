# 극단 입력 12종 테스트 결과 (카드 3)

**관련 문서:** [[meme-card-maker/README|README]] · [[meme-card-maker/docs/00_과제_요구사항_매핑|과제 요구사항 매핑]] · [[meme-card-maker/트러블슈팅|트러블슈팅]]

`js/models/FixtureData.js`의 `TEXT_CASES` 12개를 기본 카드 상태(1:1 비율,
텍스트 상자 x=8%,y=62%,w=84%,h=30%, 최대 글자 크기 12%)에서 `CardRenderer.renderCard()`로
직접 렌더링해 실제 결과값(`didClip`, `didShrink`, `finalFontSizePx`)을 확인했다.
추가로 5개 이미지 fixture(정사각형·세로·가로·투명·복잡한 사진풍) × 2가지 fit 모드
(cover/contain)에서도 오류 없이 렌더링됨을 확인했다(총 36개 텍스트×비율 조합 +
10개 이미지×모드 조합, 실패 0건).

## 결함 상세: overflow-paragraph fixture 길이 부족

- **증상**: 애초 작성한 오버플로우 검사 문구(약 280자)가 최소 폰트 크기(10px)에서도
  텍스트 상자(324px 높이, 907px 너비)에 다 들어가 버려 `didClip=false`로 나옴 —
  클립 안전망이 "한 번도 실행되지 않고" 통과 처리되는 상태였다.
- **원인**: 상자 크기·최소 폰트 크기 기준 필요 줄 수를 어림짐작으로 정해서 실제
  `canvas.measureText()` 폭과 맞지 않았다.
- **조치**: 브라우저에서 직접 `CardRenderer.renderCard()`를 호출해 문자 수를 1125자
  → 3000자 → 4500자로 늘려가며 실측, 4500자(문장 60회 반복)에서 `didClip=true`가
  안정적으로 나오는 것을 확인하고 `FixtureData.js`를 갱신했다.
- **재발 방지**: 이런 종류의 "특정 조건에서만 성립하는" fixture는 코드만으로 옳다고
  가정하지 않고, 반드시 실제 렌더 결과(`didClip` 값)를 실측해서 데이터를 확정한다.
